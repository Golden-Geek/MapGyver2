## Current work

M01.C01 is split into measured steps. First establish a real native D3D11 shared
texture baseline, then compare owned/imported texture behavior through bgfx.
The baseline is not a replacement renderer decision and does not satisfy C01's
bgfx path. It uses two devices on the same physical adapter, NT shared handles,
keyed mutex ownership, bounded GPU completion queries and exact raw-pixel checks
across two formats and three resolutions. Staging readback is explicitly for
validation outside any render deadline, and is counted separately from uploads
and GPU copy submissions. These are API counts, not hardware bus counters.

## Candidate source inspection

The pinned vcpkg registry selects bgfx 1.129.8940-496#1. Its official archive was
downloaded to ignored out/research/bgfx and SHA512 verified against the port:
`520c542b65e76e92eae818e32eeb62bb2347ac89a1e10fc07cd5059a3b8a9a543cadca87d451a3bc157c415f6183b1f0e5031248e38fae704b8efd54679d482b`.
The current online docs describe a newer API; use the pinned source for behavior.
In that source renderer_d3d11.cpp lines 4729–4760, overrideInternal marks an
external texture internally shared and does not AddRef/Release the raw resource.
The caller must retain it through bgfx view destruction and GPU completion.
platform.h requires internal-data/override calls on the render thread; these
constraints must be exercised rather than bypassed with unmeasured ownership.

## bgfx sampling (M01.C01 working-tree validation)

Pinned bgfx 1.129.8940-496#1 and SDL3 3.4.18 built successfully. The optional
windows-bgfx profile keeps these out of portable core builds. No renderer fork
was introduced; the registry's standard dependency-wiring patch is retained.
Verified example shader binaries are embedded with their source/provenance and
BSD-2-Clause notice. Resolved dependency/notice identity is recorded separately.

The Release probe passed 12 cases: owned and cross-device shared imported
textures, RGBA8/BGRA8 at 64/128/256, with exact color/alpha and generation checks.
Native resources remain held through view destruction and GPU completion. Each
case records one source upload call, one sampling draw, one validation GPU copy
and one validation readback; these are API submissions, not hardware counters.

Initial Debug runs timed out at 30 seconds. Pinned bgfx.cpp lines 1473–1514 showed
renderFrame() asserts when BGFX_CONFIG_MULTITHREADED=0, before the init callback
exists. The manifest deliberately disables that feature; removing the invalid
pre-init call fixed the cause. Debug then passed the same 12 cases. Assertions
were not disabled or timeouts extended. Fatal callbacks now fail with bounded
diagnostics, including DebugCheck; optional profiler/cache callbacks make no
success/capability claims. Both builds still require a clean committed GPU rerun.

The real hardware test also holds the producer keyed mutex in a separate run.
Consumer AcquireSync returns WAIT_TIMEOUT (0x102), the process exits 1 without
success JSON, and cleanup finishes within the unchanged process timeout. The
Debug and final Release hardware contracts passed; hosted compile remains
pending. A concurrent documentation/inventory update briefly caused the Release
plan contract to reject a link before its inventory file existed. The inventory
is now generated; the full Release wrapper rerun passed all five CTest contracts.
No check was skipped or weakened. Debug wrapper/build/CTest also passed all five.
Reports are under out/reports/bgfx-hardware-*; source is fc168c5 plus these
uncommitted changes, accurately reported as sourceDirty=true.

Spout external-peer, hardware-decoder import, physical two-output and performance
results remain open. M01.C02–C04 are pending. Laptop only; two-output/hotplug gates
remain open. Do not qualify M01 or dependent milestones from these texture probes.
