## Current work

M01.C01 is split into measured steps. First establish a real native D3D11 shared
texture baseline, then compare owned/imported texture behavior through bgfx.
The baseline is not a replacement renderer decision and does not satisfy C01's
bgfx path. It uses two devices on the same physical adapter, NT shared handles,
keyed mutex ownership, bounded GPU completion queries and exact raw-pixel checks
across two formats and three resolutions. Staging readback is explicitly for
validation outside any render deadline, and is counted separately from uploads
and GPU copy submissions. These are API counts, not hardware bus counters.

## Candidate source inspection

The pinned vcpkg registry selects bgfx 1.129.8940-496#1. Its official archive was

`520c542b65e76e92eae818e32eeb62bb2347ac89a1e10fc07cd5059a3b8a9a543cadca87d451a3bc157c415f6183b1f0e5031248e38fae704b8efd54679d482b`.
The current online docs describe a newer API; use the pinned source for behavior.
In that source renderer_d3d11.cpp lines 4729–4760, overrideInternal marks an
external texture internally shared and does not AddRef/Release the raw resource.
The caller must retain it through bgfx view destruction and GPU completion.
platform.h requires internal-data/override calls on the render thread; these
constraints must be exercised rather than bypassed with unmeasured ownership.

Pinned libavcodec/dxva2.c lines 505–563 and 659–703 establish that the selected

Returned samples must have an actual same-device NV12 array texture with
D3D11_BIND_DECODER and valid slice. This is native D3D11VA path evidence, not a
hardware engine counter. Public ownership semantics are also documented by
[FFmpeg's D3D11VA API](https://www.ffmpeg.org/doxygen/9.0/hwcontext__d3d11va_8h_source.html).

Local Debug and Release wrappers passed all five CTest contracts. Native trials
passed 54 decoded/rendered frames per configuration across three independently
created generations (128/256/128), retaining samples until GPU completion.
The GPU video processor converts NV12 using explicit BT.601 limited-range to
BGRA full-range settings before bgfx sampling. Every pixel is compared against
software decode of the same encoded bytes and an independently written BT.601
conversion; maximum observed error was one code value, below the fixed two-value
rounding tolerance. The real hardware-format refusal test returned FFmpeg's
AV_PIX_FMT_NONE error, exit 1 and no success payload. No fallback or success was
mocked. Fixture media is authored in memory, bounded and hashed, with no copied
third-party media. Reports contain PTS/time base, slices, applied bgfx frames,
explicit API counts, RAM/VRAM snapshots and first/warm offline timing percentiles.

These times include GPU conversion/render/validation and waits/readback, and
exclude packet-submission time. They are not full decode latency, sustained
throughput, show deadline or scanout evidence. Memory values are actual snapshots,
not a leak bound or ratified performance budget. Current native reports are
f40e890 plus sourceDirty=true; clean committed reruns and hosted compilation
remain pending. This partial C03 slice does not qualify other codecs, in-stream
