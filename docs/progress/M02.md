# M02 — domain model and parameter registry

Status: **in progress, independent portable implementation only**. M01 still
requires physical-output, device-loss and sustained-workload qualification;
M02 cannot be completed/tagged ahead of that dependency. No renderer choice
or native output behavior is inferred from these model tests.

## M02.C01 definition graph slice

The new portable C++20 domain library defines opaque stable IDs, reusable assets,
named typed ports, composition inputs/outputs and ordered layer bindings.
Composition assets reference definitions, never GPU, decoder, process or UI
objects. Default input slots can remain unbound. Unknown configured adapters
are retained as definitions, with no availability/readiness claim.

Control publishes an immutable DefinitionSnapshot only after all references,
port types, local sharing groups and dependency cycles validate. Explicit local
shared groups must use the same asset; the future live instance scope will
materialize each composition placement independently. Input slots do not create
fixed asset dependencies; actual input/source instance bindings require a
separate live-graph cycle check before activation. Source instance ownership,
transport state and lifecycle are not implemented by this first slice.

Validation reports stable involved IDs for direct/indirect cycles and uses
iterative DFS rather than recursive calls. Meaningful C++ contracts cover a
2,048-level valid graph and full cycle path, immutable snapshots, rename/reorder
identity, 18 named outputs, typed-port rejection, explicit sharing constraints,
missing references, duplicate IDs/names, UTF-8/control-character errors and
retention of an unknown adapter/endpoint. Runtime checks stay enabled in Release;
the tests do not use assertions that NDEBUG would remove.

`python tools/ci/check.py --preset windows-local --configuration Debug
--skip-bootstrap` passed the real build and all six CTest contracts, including
domain.definitions. Release passed the same real build and all six contracts.
Hosted native Linux/macOS/Windows checks are pending. This working tree is based
on dcf804e plus dirty=true. This is model
evidence, not decoder/transport/network/persistence/OSCQuery qualification.

Next C01 slice: scoped live source instances and independent transport, explicit
sharing/lifecycle reference policy, composition instantiation and live binding
cycle/capacity rejection. Keep definitions separate from per-instance state.

## M02.C01 instance ownership slice

InstancePool now materializes source instances separately from definitions.
Each placement and nested composition owns independent child state by default;
local shared groups are scoped to their parent live instance. Explicit existing
instance/port bindings reuse one owner across consumers, including distinct
ports. Input-slot imports create independent sources by default. Each owner
holds rational transport intent and keep-alive policy, with exact owner-reference
counts. Last-reference retirement is iterative; shared descendants survive until
their remaining owner releases them. Retired IDs are logical disposal requests,
not claims that an SDK/app stopped.

Structural edits validate a candidate before publication. Actual live input
bindings have a separate iterative cycle check. Configurable instance,
placement and ownership-edge capacities reject nested expansion atomically.
Tests cover independent/shared transports, nested sharing scope, cross-scope
explicit consumers, typed input assignment, direct/indirect live cycles and
rollback, keep-alive release, invalid rational intent, all three capacities and
2,048-deep instantiation/retirement without recursive stack use.

The final Debug and Release windows-local wrappers pass all seven contracts,
including preloaded nested ownership and ID-collision rollback cases. Clean
committed and hosted evidence are pending for this working tree, based on
fe7f107 plus dirty=true. Actual decoder state/readiness, mutable definition
reconciliation, parameter registry, surfaces/projectors and persistence remain
subsequent slices. M02 is not complete; M01 qualification gates stay open.

## M02.C02 stage/layout/calibration slice

StageSnapshot now validates arbitrary surface/group/layout/output/patch maps.
Surfaces consume a video composition output through a distinct logical placement
lease; several leases can deliberately share one live composition. Continuous
layouts require that shared instance/port and explicit per-surface UV charts.
Independent layouts permit different content. Optional boundary-edge seams are
metadata, not an inferred physical unfolding or scanout guarantee.

Source-local, surface UV, composition UV and projector-pixel coordinates are
separate fields. Stable point IDs own topology and calibration boundaries.
Finite coordinates, face references, nondegenerate/unique triangles, convex
ordered homography quads, group/chart membership and configurable entity/geometry
capacities validate before publication. Mesh calibration is an explicit mode.
Logical canvas dimensions/formats belong to composition outputs; desired modes
and bindings belong to outputs; calibration and its reference resolution belong
to patches. Unknown output/format declarations remain configured, with no runtime
support claim. Neither content assignment nor desired-mode changes rewrite them.

The default logical project creates root composition/input/default content slot,
Program canvas, one surface, one desired output and a four-corner patch. The show
root has its own ownership lease, independent of surface consumers. Tests bind
registered media to that slot and change rational transport intent while proving
calibration stays identical. Actual import/probing/playback remains later work.

Native Debug and Release wrappers pass all eight CTest contracts. Stage scenarios
cover 1/3/37 surfaces, continuous/independent content, explicit UV seams/charts,
one surface spanning outputs and one output receiving multiple surfaces,
unsupported output retention, calibration preservation and invalid geometry,
binding/topology/capacity rejection. The initial Debug stage test crashed because
it retained a map-key reference across map replacement; owning that ID fixed the
test lifetime bug. The full suite then passed; no assertion/timeout was weakened.
Current source is 4d1efdb plus dirty=true; clean committed/hosted checks pending.
