Status: **in progress, independent portable implementation only**. M01 still

## M02.C01 definition graph slice

The new portable C++20 domain library defines opaque stable IDs, reusable assets,
named typed ports, composition inputs/outputs and ordered layer bindings.
Composition assets reference definitions, never GPU, decoder, process or UI
objects. Default input slots can remain unbound. Unknown configured adapters
are retained as definitions, with no availability/readiness claim.

Control publishes an immutable DefinitionSnapshot only after all references,
port types, local sharing groups and dependency cycles validate. Explicit local
shared groups must use the same asset; the future live instance scope will
materialize each composition placement independently. Input slots do not create
fixed asset dependencies; actual input/source instance bindings require a
separate live-graph cycle check before activation. Source instance ownership,
transport state and lifecycle are not implemented by this first slice.

Validation reports stable involved IDs for direct/indirect cycles and uses
iterative DFS rather than recursive calls. Meaningful C++ contracts cover a
2,048-level valid graph and full cycle path, immutable snapshots, rename/reorder
identity, 18 named outputs, typed-port rejection, explicit sharing constraints,
missing references, duplicate IDs/names, UTF-8/control-character errors and
retention of an unknown adapter/endpoint. Runtime checks stay enabled in Release;
the tests do not use assertions that NDEBUG would remove.

`python tools/ci/check.py --preset windows-local --configuration Debug
--skip-bootstrap` passed the real build and all six CTest contracts, including
domain.definitions. Release passed the same real build and all six contracts.
Hosted native Linux/macOS/Windows checks are pending. This working tree is based
on dcf804e plus dirty=true. This is model
evidence, not decoder/transport/network/persistence/OSCQuery qualification.
