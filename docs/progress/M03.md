# M03 progress - control service and remote contract

Status: in_progress, independent portable implementation. M02/M01 qualification
remains open; M03 cannot be completed ahead of those dependencies.

## M03.C01 reliable session core

ControlService now binds client/session/service identity, validates strict
versioned request envelopes and routes structural/parameter/undo/redo operations
through the authoritative controller/registry. It implements expected authored
revisions, single editing ownership, observer access and explicit ownership
generation/transfer/release. Accepted replies identify authored publication only;
native rendering and persistence remain unavailable with explicit reasons and
null applied/saved revisions. Non-null show scheduling is rejected visibly.

Sequence-scoped terminal response caches support reconnect/lost-ack retries;
payload mismatches, gaps and expired sequences never execute. Both accepted and
rejected outcomes are retained. Cache eviction preserves sequence watermarks;
session retention is bounded by a monotonic control-clock deadline and does not
evict retained identities early under pressure. Service restarts change identity.
Subscription cursors recover bounded journal batches or a complete current
snapshot when older events were evicted. No unbounded subscriber queue exists.
Serialized snapshot, response/cache and journal reservations precede publication;
over-budget state changes roll back instead of becoming uninspectable.

The initial protocol test exposed a stale-revision reply using the registry's
internal stale_snapshot code. An explicit service-boundary authored revision
check now returns revision_conflict consistently; assertions were not weakened.
Final Windows Debug/Release wrappers each pass all twelve contracts on 25de351
plus dirty=true, including byte-budget reply eviction, expired mutation replay
refusal, request size rejection and remote structural-batch rollback.
[Detailed contract](../../libs/protocol/README.md). Clean committed/hosted checks
follow after commit.

This slice is portable in-process control/session evidence. It does not implement
or qualify named-pipe IO, remote sockets, OSCQuery, actual native applied outcomes,
durable saving, UI/preview or managed-app launch deduplication. Those remain open;
the next C01 slice connects the real engine through bounded Windows named-pipe IO.

## M03.C01 native named-pipe engine slice

`--serve --pipe-name <stable-id>` now starts the actual Windows engine/control
service. Private adapter code owns current-user protected DACL, remote rejection
and first-instance flags, overlapped IO and completion lifetimes. Byte frames,
peer buffers and frame/write deadlines are bounded; slow or malformed peers close
without blocking other clients. Kernel write completion is distinguished from
application receipt; reconnect uses actual client event cursors and explicit
subscriptions. Native renderer/durable storage remain visibly unavailable.
[Transport contract and API sources](../../adapters/windows/PIPE_CONTROL.md).

Independent ctypes clients exercise the real executable in separate processes.
Twelve native phases pass: fragmented handshakes, actual current-user DACL
readback, lost-ack reconnect/replay, ownership/revision/readonly validation, push
notifications/calibration preservation, malformed JSON and bad frame lengths,
partial header/body deadlines with healthy client progress, twenty native peer
recycles with equal actual handle counts, real output-buffer stalls/write timeout,
cancelled large reply/cache recovery, namespace collision and owned process restart.
No hardware counters, renderer frames, durable saves or remote-SMB test success is
inferred. The restart intentionally stops only the test-owned process.

returned Win32=231. A controlled independent SDK probe established access denial

still responds. No SDK failure is treated as success. Final local Debug/Release

## M03.C02 portable OSC/OSCQuery adapter slice

The authored bounded OSC codec implements mandatory wire scalars/blob/string,
selected extended tags, explicit endianness/padding, nested bundle order and exact
NTP bits, with malformed/nonfinite/UTF-8/capacity rejection. Registry-backed Tree
exposes every existing parameter/action through query metadata, preserves exact
rational/uint64 values and maps incoming values/actions to the same typed validator.
Subscription implements exact LISTEN/IGNORE filtering and structure invalidation.
Ingress starts read-only, requires editing-owner transfer, validates complete
bundles before one transaction, and visibly rejects unavailable scheduling or
unsupported mixed/history grouping. [Detailed contract](../../libs/protocol/OSC_QUERY.md).

Tests cover independent golden bytes, all implemented tags, nested order/timetags,
corruption/capacities, complete inventory, access/range/default/identity metadata,
exact numeric/structured round trips, rename/structural differences, exact-path

## M03.C02 actual native loopback sockets

The engine's optional `--oscquery` mode now binds actual loopback HTTP/UDP/
WebSocket endpoints using pinned Boost.Beast/Asio 1.92.0. One control owner polls
bounded asynchronous completions. The registry supplies the complete HTTP tree,
HOST_INFO/actual ports, exact LISTEN/IGNORE binary values and structural root
PATH_CHANGED. Converted writes use the same service validator. The external OSC
channel starts read-only and requires an explicit generation-checked editing-owner
transfer over the current-user pipe. This grant covers all local OSC peers, not
individual authenticated clients. [Transport contract](../../adapters/osc/NETWORK.md).

Independent Python stdlib HTTP/UDP/masked RFC6455 clients exercise real sockets:
complete registry parity/metadata/Host/Origin/method policy, UTF-8 UDP and atomic
bundle/type/timetag rejection, fragmented binary WebSocket values, exact-path
LISTEN/IGNORE/reconnect, structural creation/PATH_CHANGED/configuration and
calibration preservation, actual kernel-buffer write stall/deadline with healthy
client progress, partial HTTP deadline, malformed/unmasked/oversized WebSocket
rejection, and actual peer-capacity refusal/recovery. Both production Windows
engine/pipe ownership and portable native socket fixture modes are exercised.
The fixture's initial ownership grant is test-only; closing parent stdin verifies
normal native fixture destruction. Production engine cleanup stops only the owned
test process and does not claim graceful OS shutdown or durable recovery.

Initial compile checks caught a shadowed local and required MSVC `/bigobj` for
Beast's template object; warnings stay errors. Client-only mistakes in module
shadowing, arbitrary inventory-size guessing and lowercasing a case-sensitive
WebSocket accept value were corrected using exact registry/header comparisons.
The initial stall observation counted ordinary HTTP closes; specific actual write
and HTTP timeout counters now identify the intended events. Windows partial HTTP
close produces native connection reset while stalled WebSocket drain produces EOF;
both are retained as actual native close classes, and timeouts remain failures.
