## M04.C01 - Immutable composition plans and native offscreen rendering

Portable plans resolve active video dependencies iteratively, retain independent
instance scope and deduplicate explicitly shared outputs. Compatible transient
targets reuse only after their final dependency use; named surface/preview roots
stay live through export. Configured unsupported canvases and missing source
frames retain objects/reasons and render transparent. Count/dimension/byte limits
reject preparation without changing authored state.

Canonical SDR pixels are linear-sRGB premultiplied floats. RGBA8 input preparation
and output encoding define the transfer/alpha order; compositing uses over and
nearest pixel-centre sampling. Contract tests independently verify known sRGB
blend values, immutable prior plans after layer reorder, scoped independence,
37 shared surfaces, invalid/conflicting generations, unavailable content, atomic
budget failure and a 2,048-deep graph using two compatible targets.

The private Windows adapter prepares all resources and authored shader binaries
before frame submission. Actual bgfx/D3D11 hardware, LUID, texture formats and
count/dimension capacities are checked. Source uploads cache resource/generation;
internal targets use RGBA16F; named RGBA8 exports encode transfer/alpha explicitly.
Dense view IDs avoid imposing a view limit on leaf source count. Offline capture
retains native resources and waits for query completion before staging readback.
The preparation path is distinct from `frame()`; no synchronous readback or
shader compilation occurs inside that function.

The manual GPU fixture exercises bars, alpha over, gradients, linear/encoded
straight/premultiplied exports, nested compatible target reuse, 300 independent
layers and genuinely unavailable frames. Eight cases submit 160 frames and
capture sixteen outputs, with fixed channel tolerance 2/255 against the portable
reference. Dirty-source Debug/Release passed on the RTX 5080 Laptop GPU (vendor 4318,
device 11353); clean committed-source Debug/Release evidence follows the code
commit. Each run records actual binary/shader/compiler hashes, source identity,
adapter identity, upload/readback bytes and GPU copy submissions separately.
Payload counts are not measured VRAM allocations or hardware transfer counters.

`windows-render` builds the native adapter/tools; `windows-ci` compiles them on
the hosted Windows runner without pretending hardware qualification. Portable
render contracts run on all foundation presets. Shader compilation is offline
using pinned shaderc 1.18.129 and its actual `s_5_0` profile. The initial
`vs_5_0` profile was rejected by that pinned tool and corrected from its CLI.
Source/shader build instructions are in [libs/render](../../libs/render/README.md).

The first Release GPU run exposed an access violation during cleanup, with
Windows reporting `d3d11.dll_unloaded`. Extra native capture COM references
outlived bgfx shutdown, which unloads its D3D11 module. The adapter now drops
those extra references before shutdown while bgfx still owns the resources
through queued destruction. Debug did not expose this ordering error. Both configurations now pass the
same captures and normal process exit;
no assertion, tolerance or deadline is weakened.

Open C01/runtime work: engine integration, hot resource preparation/handoff,
native applied-frame reporting and encoded preview. C02 persistent native output
targets, C03 physical mapping/masks/color rules and C04 browser-loss/multi-output

deadline budgets or device-loss recovery. M01 external hardware gates and
ADR-011/ADR-015 remain open. No milestone tag is authorized by this evidence.

## M04.C02 - Persistent bindings and native window API slice

Authored output enable/blackout/freeze controls use the shared typed registry,
atomic transactions/history and generated wire schema/editor types. Calibration
and content ownership remain separate. Portable bounded binding compares exact
stable desired endpoints/modes with a supplied capability/display inventory;
unbound, absent, ambiguous, disabled, unsupported or oversized objects retain
configuration and a reason. A ready binding is eligible for native preparation,
not a claim of presentation. Contracts cover enumeration reorder, ambiguous/missing
targets, rational mode equality, retained unknown NDI objects, 37 independent
logical windows, capacity failure, typed round trip and undo.

The native compositor now prepares independent SDL windows/bgfx D3D11 swapchains,
per-output held frames and opaque presented textures. Freeze begins black until
a complete frame has been submitted; blackout overrides the presented image
without destroying the held frame, and disable blacks/hides without deleting
logical identity. Unfreeze updates on the next frame. Native show time and other
outputs continue. Output controls and captures require the same GPU owner thread.
Prepared output roots stay live through their downstream consumers. Count/view/
texture/payload bounds include owned held/presented textures; driver swapchain
backbuffer allocations are not claimed as measured texture payload or VRAM.

The explicit native GPU fixture creates three hidden windows at 128x64, 97x53
and 64x32. Thirteen software frames and eleven offline captures check initial
freeze, unfreeze, independent progress, blackout, disable and restoration of a
held frame. Display reference composites linear premultiplied content over black
before sRGB encoding, rather than displaying straight alpha RGB directly. Tolerance
remains fixed at 2/255. Captures sample the exact intermediate textures submitted
to the swapchains; they do not establish backbuffer receipt or physical scanout.
Static source content and software held-frame identities are tested; media/source
generation changes while frozen remain unqualified. Dirty-source Debug/Release wrappers pass 23/23; composition goldens and all
eleven output captures pass in both configurations. A known half-alpha blue
reference verifies opaque display value 188/255, and a foreign thread is refused
before mutating native controls. Clean committed-source evidence follows.

Open C02: actual Windows monitor inventory, persistent binding/window orchestration,
native render/control worker resource handoff, engine applied-frame/status and
production browser-loss scenarios. Whole-window composition presentation does
not implement projection-patch mapping; C03 remains open. [Runtime scope and
commands](../../libs/runtime/README.md). No M04 completion/tag.
