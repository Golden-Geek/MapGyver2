## M04.C01 - Immutable composition plans and native offscreen rendering

Portable plans resolve active video dependencies iteratively, retain independent
instance scope and deduplicate explicitly shared outputs. Compatible transient
targets reuse only after their final dependency use; named surface/preview roots
stay live through export. Configured unsupported canvases and missing source
frames retain objects/reasons and render transparent. Count/dimension/byte limits
reject preparation without changing authored state.

Canonical SDR pixels are linear-sRGB premultiplied floats. RGBA8 input preparation
and output encoding define the transfer/alpha order; compositing uses over and
nearest pixel-centre sampling. Contract tests independently verify known sRGB
blend values, immutable prior plans after layer reorder, scoped independence,
37 shared surfaces, invalid/conflicting generations, unavailable content, atomic
budget failure and a 2,048-deep graph using two compatible targets.

The private Windows adapter prepares all resources and authored shader binaries
before frame submission. Actual bgfx/D3D11 hardware, LUID, texture formats and
count/dimension capacities are checked. Source uploads cache resource/generation;
internal targets use RGBA16F; named RGBA8 exports encode transfer/alpha explicitly.
Dense view IDs avoid imposing a view limit on leaf source count. Offline capture
retains native resources and waits for query completion before staging readback.
The preparation path is distinct from `frame()`; no synchronous readback or
shader compilation occurs inside that function.

The manual GPU fixture exercises bars, alpha over, gradients, linear/encoded
straight/premultiplied exports, nested compatible target reuse, 300 independent
layers and genuinely unavailable frames. Eight cases submit 160 frames and
capture sixteen outputs, with fixed channel tolerance 2/255 against the portable
reference. Dirty-source Debug/Release passed on the RTX 5080 Laptop GPU (vendor 4318,
device 11353); clean committed-source Debug/Release evidence follows the code
commit. Each run records actual binary/shader/compiler hashes, source identity,
adapter identity, upload/readback bytes and GPU copy submissions separately.
Payload counts are not measured VRAM allocations or hardware transfer counters.

`windows-render` builds the native adapter/tools; `windows-ci` compiles them on
the hosted Windows runner without pretending hardware qualification. Portable
render contracts run on all foundation presets. Shader compilation is offline
using pinned shaderc 1.18.129 and its actual `s_5_0` profile. The initial

## M04.C02 - Engine native owner and applied-frame bridge

The engine's opt-in `--render` path runs prepared composition content on its own
GPU/window owner. Its frame loop, clock and output hold/presentation do not use
browser callbacks, preview subscribers or client requests. Bounded value batches
carry validated output flags and metadata revisions; the worker tries each
control/status lock once and keeps rendering if a control observer is busy.
Resources and SDK calls stay on the native owner, with actual completion before
thread/resource disposal and a five-second fatal shutdown boundary.

ControlService consumes actual observations on its control owner. Generation,
applied revision, software frame and rational monotonic show time remain readonly
and separate from authored/saved status. First application/revision/reason changes
produce bounded journal events; frame ticks only update observations. Old cached
terminal replies remain unchanged by newer telemetry. Portable contracts cover
old/future/regressing frames, worker generations, clock continuity, last applied
state on failure and no per-frame event flood. These supplied-observation unit
contracts are not GPU evidence.

Startup resolves explicit logical target bindings and prepares canonical full-quad
whole-window presentation. Unsupported/missing source/target configurations retain
their objects and unavailable reasons. Metadata-only changes and output flags apply

## M04.C01/C02 - Fixed-layout live image handoff

The renderer now accepts an opaque background-prepared image generation for its
existing node/target/surface layout. Startup sampled textures use DEFAULT usage;
live updates copy immutable candidates into those owned textures before drawing.
No texture, handle, SRV or query is created during application. Same-context
command order protects previous frame reads; a preallocated event query covers
candidate source reads. Normal operation polls completion once without waiting.
A pending copy returns backpressure with caller ownership intact. After actual
completion, retired native source textures and the previous immutable CPU plan
return to preparation for disposal. Shutdown has a separate bounded completion
drain and fatal owned-process cleanup if it cannot finish safely.

Preparation validates stable identities/dimensions, target/export layout, draw
capacity and dependency order. Application rejects stale scene/resource epochs,
old revisions and textures from another device before the first copy. A candidate
is bounded to 256 images/128 MiB and active plus candidate payload to 512 MiB;
the caller must separately account for other queued jobs. This is a GPU copy per
source, reported separately from CPU upload bytes, rather than a zero-copy claim.
